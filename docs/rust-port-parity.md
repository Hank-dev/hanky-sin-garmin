## A2. Native-vs-shared boundary

- **Native Rust/egui must own:** shell/navigation/subtabs, all inputs/validation/transient chat state/date-range filters/confirmations, chart rendering and sparse/learning/error states; SQLite connection/migration/transaction layer; derived metrics, statistical inference and deterministic fitness engine; Garmin auth/refresh and API mapping or a clearly maintained isolated connector; secure Anthropic HTTP boundary; Strong CSV and Hevy importer; opt-in background jobs and CLI/bot integration if claiming full-product parity. Merely launching Streamlit or embedding a web view is **not native egui parity**. [`app.py:L19-L44`; `db.py:L10-L217`; `analysis.py:L1-L210`; `ai.py:L519-L603`; `ingest.py:L177-L434`; `import_hevy.py:L274-L469`]
- **Can safely reuse as artifacts/contracts:** existing local SQLite file and column names/ID conventions, deterministic synthetic fixture/golden-output tests, catalog/standards tables, prompt wording subject to explicit outbound-AI consent, visual assets/fonts and validated chart labels. A Rust process cannot directly import Python functions without retaining a Python runtime; sharing a *data format* or running an optional isolated bridge is not equivalent to having ported the engine. Never ship private `.env`, `garmin.db`, `.garmin_tokens`, raw payloads, or personal sample data. [`db.py:L10-L282`; `strength_catalog.py:L1-L40`; `AGENTS.md:L12-L19`, `L63-L75`]
- **Privacy rule:** offline local read/render/analytics require no network; Garmin sync and explicit AI actions have distinct network destinations. Source weekly summary is an exception to “only explicitly clicked AI”: it sends automatically on cache miss when a key is configured. Native product should require explicit opt-in or document that behavior rather than inherit it invisibly. AI payloads should remain compact/derived; source retains raw Garmin payloads **locally**. [`views/cockpit.py:L291-L324`; `ai.py:L519-L586`; `ingest.py:L1-L6`; `AGENTS.md:L12-L19`]
